# little by little

예원님의 영어 말하기 기록과 매일 복습을 위한 반응형 웹 프로토타입.

## 실행

Node.js 20 이상에서 `npm run dev` 후 http://127.0.0.1:5173 열기. 외부 패키지 설치가 필요하지 않습니다.

## 구현된 기능

- 오늘의 대시보드, 실제 복습 기록 기반 주간 달력 및 연속 복습 일수
- 영어 표현 입력·저장·검색·주제 필터·삭제
- 지원 브라우저의 영어 음성 인식 및 TTS
- 정답 공개형 복습: 더 연습하면 1일 뒤, 기억하면 3일 뒤부터 두 배 간격(최대 30일)
- 일일 복습 목표, JSON 기록 내보내기
- localStorage 저장, 샘플 콘텐츠 표시, 모바일 하단 내비게이션

## 범위

현재 AI 대화, 자동 번역 및 교정, 로그인, 클라우드 동기화, 사이트 밖 푸시 알림은 연결되어 있지 않습니다. 음성 인식은 브라우저 및 마이크 권한에 따라 달라집니다. 음성은 브라우저 제공 업체에서 처리할 수 있습니다. Google Fonts가 차단된 환경에서는 시스템 글꼴을 사용합니다.

다음 단계에서는 서버를 추가해 AI 대화와 표현 추출을 연결하고 계정별 저장 및 복습 알림을 구현할 수 있습니다. API 키는 브라우저 코드에 포함하지 않아야 합니다.

## 확인

`npm run check`로 JavaScript 구문을 확인합니다.

UI 방향은 헤이링의 대화 중심 학습 흐름을 참고하되, 별도 브랜드와 초록색 노트 스타일로 구성했습니다.

## 헤이링 복습 + OpenAI 설정

헤이링 복습 탭에서 학습 내용(최대 8,000자)을 붙여넣습니다. 메모 저장은 무료 로컬 기능이며 AI 정리 버튼만 서버의 OpenAI Responses API를 호출합니다. 최대 5개 표현을 검토·선택해 저장하면 기존 복습 일정에 포함됩니다. 동일한 영어 표현은 중복 저장하지 않습니다. 캡처 이미지 입력은 아직 지원하지 않습니다.

기존 API 키는 채팅에 보내지 말고 프로젝트 루트의 `.env.local`에 직접 설정하세요. `.env.example`에 변수 이름이 있습니다. `.env.local`은 Git에서 제외되고 웹 서버에서도 제공되지 않습니다. `OPENAI_API_KEY`를 채운 뒤 서버를 재시작하세요. 기본 모델은 `gpt-6-luna`이며 `OPENAI_MODEL`로 변경할 수 있습니다. 서버 환경 변수로 제공해도 됩니다. 키가 없으면 AI 요청에 설정 안내를 반환하고 다른 기능은 유지됩니다.

자동 충전/결제 설정은 이 앱이 변경하지 않습니다. OpenAI 결제 화면에서 별도로 확인하세요. 요청은 수동 실행, 동시 1개, 5초 간격, 출력 최대 1,800토큰으로 제한됩니다. 이 제한은 월간 금액 한도나 무료 크레딧 전용 사용을 보장하지 않습니다. 계정에 유료 잔액/자동 충전이 있다면 해당 결제 설정에 따라 차감됩니다.

녹음은 MediaRecorder로 최대 60초까지 기기 메모리에서 처리하며 OpenAI에 전송하지 않습니다. 다시 듣기/다운로드가 가능하고 화면 이동이나 새로고침 시 사라집니다. 녹음은 자동 발음 평가가 아닙니다. 예시 음성은 여전히 브라우저 TTS입니다.

`npm test`는 외부 API 호출 없이 요청 검증·키 누락·교차 출처 차단·정리 결과·호출 제한·오류 비밀 보호를 검사합니다. 실제 키로의 요청과 브라우저 마이크 동작은 별도 확인이 필요합니다.

## 계정과 초대 공유

**Node.js 24 이상이 필요합니다.** ‘함께 공부’에서 아이디·비밀번호로 계정을 만들고 로그인할 수 있습니다. 로그인 뒤의 기록은 `data/study.sqlite`에 계정별로 저장되며, 로그인하지 않은 기존 브라우저 기록은 자동 업로드하지 않습니다. ‘기존 기록 가져오기’를 선택하면 샘플을 제외한 표현·메모·복습 이력을 본인 계정에 가져옵니다. 가져온 기록은 비공개입니다.

- 암호는 scrypt와 계정별 salt로 저장합니다. 인증 세션은 임의 토큰의 해시를 서버에 저장하며 HttpOnly/SameSite 쿠키를 사용합니다. HTTPS 운영 시 Secure 쿠키가 적용됩니다.
- 초대는 24시간·한 번만 사용 가능하며 취소할 수 있습니다. 링크 토큰은 URL fragment에 넣어 HTTP 요청과 referrer에 포함되지 않게 하고, 페이지 진입 시 주소창에서 제거합니다. 수락하려면 로그인해야 합니다. 로그인 과정에서 새로고침했다면 초대 링크를 다시 열어야 합니다.
- 친구 관계는 양방향입니다. 함께 보기 기록만 연결된 **모든** 친구에게 공개합니다. 친구별 선택 공유는 아직 지원하지 않습니다.
- 공개되는 필드는 표현/뜻/분류 또는 메모/날짜뿐입니다. 원본 복습 이력·다음 복습일·음성은 공개하지 않습니다.
- 공유 표현 가져오기는 새 비공개 복습 항목을 만듭니다. 원본의 진도는 복사하지 않습니다. 공유 해제나 친구 연결 해제는 이후 접근을 차단하되 이미 가져온 사본은 지우지 않습니다.
- 다른 기기의 변경이 있으면 버전 검사로 저장을 중단합니다. 화면의 기록을 다운로드하고 서버 최신 기록을 불러와 충돌을 해결합니다. 자동 병합은 지원하지 않습니다.
- 계정 삭제, 비밀번호 재설정, 이메일 인증은 아직 구현하지 않았습니다. 현재는 소규모 개인 테스트용입니다.

### 온라인 운영 준비 및 아직 필요한 단계

현재 코드는 로컬 구현이며, 온라인 서비스나 Porkbun DNS는 아직 설정하지 않았습니다. localhost 초대 링크는 다른 기기에서 사용할 수 없습니다.

계정·초대·공유 권한은 GitHub 파일 대신 서버 데이터베이스에서 관리합니다. GitHub에는 코드만 올리고 `data/`, `.env.local`은 절대 올리지 않습니다.

이 버전은 지속 디스크를 제공하는 Node 24 호스팅을 대상으로 합니다. 일반적인 일회성 서버리스 함수에 SQLite 파일을 넣으면 기록이 유실될 수 있습니다. 맥북 없이 쓰려면 다음이 필요합니다:

1. Dockerfile 또는 Node 24로 실행 가능한 호스팅 계정 연결.
2. `/app/data`에 지속 디스크 마운트. 단일 인스턴스로 운영하고 정기 데이터베이스 백업 설정.
3. 호스팅 비밀 설정에 `OPENAI_API_KEY`, `APP_ORIGIN=https://english.3dowon.com`, `DATA_PATH` 등록. 로컬 env 파일 업로드 금지.
4. 호스팅 제공 업체에서 발급한 정확한 DNS 대상을 Porkbun에 연결하고 HTTPS 활성화.
5. 실제 외부 주소에서 두 계정 로그인, 초대, 공유·해제, 기기 간 저장 검증.

`APP_ORIGIN`을 지정하면 해당 Host 및 Origin만 허용하고 외부 바인딩(0.0.0.0)을 사용합니다. 미지정 시 loopback 전용으로 실행됩니다. 공개 서비스로 확대하기 전에는 복구 가능한 인증 서비스와 운영 수준의 요청 제한을 추가해야 합니다. Sites 호스팅으로 옮길 경우 해당 플랫폼의 인증과 D1 저장소로 별도 전환해야 하며, 현재 SQLite/자체 로그인을 그대로 올리면 안 됩니다.

AI 호출은 최초 가입 계정(운영자)과 그 계정에 초대 관계로 연결된 계정만 허용합니다. 무관한 신규 계정끼리 초대해도 AI 호출 권한은 생기지 않습니다. 배포를 외부에 알리기 전에 운영자가 최초 계정을 만들어야 합니다. 여러 탭에서 로그인 계정이 달라지면 기존 탭의 계정 데이터를 읽거나 저장하는 요청을 차단합니다.

## 공개 GitHub + Pages 배포

현재 선택한 방향은 GitHub Pages에 화면을 배포하고 별도 서버에서 인증/학습 기록/AI 요청을 처리하는 방식입니다. 이메일 없이 아이디·비밀번호를 사용합니다. 비밀번호 원문은 보관하지 않습니다.

`npm run build:pages`는 명시적으로 허용한 정적 파일 5개만 `dist-pages/`에 생성합니다. 저장소 루트 전체를 Pages 배포 대상으로 선택하지 마세요. `.github/workflows/pages.yml`은 이 정적 폴더만 업로드합니다. GitHub 저장소 Settings → Pages → Source를 GitHub Actions로 설정해야 합니다.

GitHub Actions Repository Variable `PUBLIC_API_BASE`가 없으면 **화면 미리보기 모드**로 빌드되어 로그인·초대·AI를 활성화하지 않습니다. 로그인과 기록 저장이 준비됐다고 오해하게 만드는 가짜 로그인은 제공하지 않습니다. 화면 기록은 해당 브라우저에만 남습니다.

실제 서버를 배포한 후 다음 값을 설정합니다(아래 주소는 계획 예시이며 배포 완료 주소가 아닙니다):

- Pages custom domain: `english.3dowon.com`
- Repository Variable `PUBLIC_API_BASE`: `https://api.3dowon.com`
- 서버 `APP_ORIGIN`: `https://api.3dowon.com`
- 서버 `FRONTEND_ORIGIN`: `https://english.3dowon.com`

서버는 지정한 화면 주소만 허용하고 쿠키 인증을 적용합니다. 양쪽 모두 같은 등록 도메인의 HTTPS 서브도메인을 사용해야 SameSite=Strict 쿠키가 동작합니다. `github.io` 화면에서 다른 업체 기본 주소로 연결하면 교차 사이트 쿠키 제한에 걸릴 수 있으므로 이 구성은 최종 사용자 도메인 연결 후 검증하세요.

`PUBLIC_API_BASE`는 공개 주소일 뿐입니다. OpenAI 키나 GitHub 토큰을 GitHub Repository Variables, config.js, HTML, Pages 산출물에 넣지 마세요. API 키는 별도 서버의 secret 설정에만 등록합니다. 학습 DB는 지속 디스크에 저장하고 공개 저장소에 커밋하지 않습니다. 원래 Sites 배포 시도 정보는 `hosted/`에 남아 있지만 이번 Pages workflow는 사용하지 않습니다.
